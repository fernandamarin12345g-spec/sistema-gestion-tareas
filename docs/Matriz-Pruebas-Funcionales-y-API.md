## 1. Matriz de Pruebas Funcionales y de API

| ID Caso | Módulo / Capa | Tipo de Prueba | Descripción del Escenario | Pasos de Ejecución | Resultado Esperado | Resultado Obtenido | Estado |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :---: |
| **CP-NAV-01** | UI / Frontend | Prueba Funcional | Navegación SPA (Single Page Application) por vistas | Hacer clic en los enlaces del menú de navegación lateral (Inicio, Tareas, Estados, etc.). | La URL cambia el `#hash` y muestra la sección activa sin recargar la página web. | Navegación fluida y sin recargas de página. | **Aprobado** |
| **CP-SYS-01** | Sistema / JS | Carga Secuencial | Inicialización estricta de módulos padre antes que los hijos | Recargar la aplicación web y observar el orden de peticiones HTTP. | Se ejecuta `await cargarEstados()`, luego `Roles`, `Usuarios` y finalmente `Tareas`. | Las listas desplegables (selects) se llenan correctamente antes de renderizar las tareas. | **Aprobado** |
| **CP-EST-01** | Estados (API) | Pruebas de API | Crear un nuevo estado via `POST` | Enviar JSON `{"nombre_estado": "En Revisión"}` a `/api/Estados`. | Responde `200 OK` y asigna un `id_estado` autoincremental en la base de datos SQLite. | Registra correctamente el estado. | **Aprobado** |
| **CP-EST-02** | Estados (API/BD) | Restricción Llave Foránea | Impedir eliminar un estado que ya está asignado a tareas | Intentar borrar (DELETE) un estado en uso desde la UI. | Atrapa `SqliteErrorCode == 19` y responde `400 BadRequest` con alerta amigable. | Bloquea la eliminación y evita registros huérfanos en BD. | **Aprobado** |
| **CP-ROL-01** | Roles (API/BD) | Validación `UNIQUE` | Prevenir creación de roles con nombres duplicados | Intentar crear un rol con un nombre ya existente en la base de datos. | Captura la excepción de integridad y retorna `400 BadRequest` notificando conflicto. | Evita roles duplicados. | **Aprobado** |
| **CP-ROL-02** | Roles (Frontend) | Prueba Funcional | Editar propiedades booleanas (`is_admin`) de un rol | Seleccionar "Editar", marcar la casilla de administrador y guardar. | Envía `PUT` usando `idRolEnEdicion` y actualiza la UI mostrando la etiqueta roja "Administrador". | Actualiza el permiso y refleja el cambio visualmente. | **Aprobado** |
| **CP-USU-01** | Usuarios (API/BD) | Integridad de Datos | Actualizar datos de usuario evadiendo conflicto con su propio correo | Editar el rol de un usuario manteniendo su correo actual intacto. | La consulta SQL verifica `WHERE correo = @correo AND id_usuario != @id` y permite el cambio. | Permite actualizar nombre y rol sin error de índice `UNIQUE`. | **Aprobado** |
| **CP-USU-02** | Usuarios (UI) | Vista Relacional | Ver tareas asignadas dentro del detalle del usuario | Abrir la tarjeta de un usuario que tenga tareas asignadas en el Grid. | La consulta `LEFT JOIN` trae las tareas y el JS dibuja una lista interna con ID, título y estado. | Muestra correctamente el historial de tareas de la persona. | **Aprobado** |
| **CP-TAR-01** | Tareas (UI/API) | Creación Completa | Seleccionar responsable y estado al crear la tarea | Llenar título, elegir usuario y estado desde los `select`, y dar clic en Crear. | El frontend envía el `id_estado` correcto y se guarda dinámicamente en la base de datos. | Tarea guardada con el estado inicial correcto. | **Aprobado** |
| **CP-TAR-02** | Tareas (Frontend) | Filtro Dinámico | Uso de botones de estado generados automáticamente | Hacer clic en uno de los botones de filtro azules (ej. "Pendiente"). | Ejecuta `filtrarVista()` comparando el estado de la tarea con el texto del botón. | Oculta las tareas que no coinciden y muestra solo las solicitadas. | **Aprobado** |
| **CP-TAR-03** | Tareas (API) | Modificación (`PUT`) | Actualizar el título, responsable o estado de una tarea | Hacer clic en "Editar", modificar datos y pulsar "Actualizar Tarea". | Envía petición `PUT` utilizando comandos SQL independientes. | Actualiza la tarea en SQLite y refresca la cuadrícula web. | **Aprobado** |
